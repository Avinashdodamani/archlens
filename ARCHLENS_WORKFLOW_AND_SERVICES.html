💡 Quick Q&A: What is the difference between the 3 tiers, and why can't we just look at Cost Explorer directly?

• What is the difference?
— Tier 1 (Dedicated Scanners) examines the deep technical security settings (Is port 22 open? Is KMS encryption on? Is Multi-AZ enabled?).
— Tier 2 (AWS Config & Tags) identifies the existence and inventory of the remaining 50+ services (e.g., OpenSearch domains, SageMaker endpoints) that don't need custom scanners.
— Tier 3 (Cost Explorer) identifies the dollar footprint across all 200+ AWS services.

• Can we see directly Cost Explorer instead of AWS Config?
Short Answer: No, because Cost Explorer only tells you money spent, not how things are configured.
1. Cost Explorer has zero security details: It tells you you spent $50 on S3, but cannot tell you if an S3 bucket is public, unencrypted, or missing MFA delete.
2. Cost Explorer has a 24-hour billing delay: If someone created an insecure database 2 hours ago, Cost Explorer won't show it yet, but AWS Config and direct scanners detect it instantly.
3. Free-tier & zero-cost resources are invisible in billing: An open security group (`0.0.0.0/0`), an unattached internet gateway, or free IAM users with admin access cost $0.00, so Cost Explorer will completely miss them!
Summary: AWS Config & Direct Scanners give Security & Architecture; Cost Explorer gives Financial Health & catches forgotten services. They work together.

🤖 3. Real-Time AI Chatbot Grounding Architecture

📌 General Note on GenAI in Cloud Governance:
Generic AI models (like ChatGPT or standalone LLMs) hallucinate because they have no access to your live infrastructure. They provide textbook AWS best practices but cannot know your actual VPC IDs, open ports, or account vulnerabilities.
🎯 ArchLens Specific Architecture:
ArchLens solves this through Strict In-Memory Grounding. Before sending a query to Amazon Bedrock Nova Pro, the backend automatically extracts the active scan from DynamoDB (e.g., Target Account ID 515554959344, 59 live resources, specific security findings) and binds it into the prompt with an active Amazon Bedrock Guardrail (303z1lw3qgz1). The AI is forbidden from guessing or inventing resources.
💡 Real-Time Working Example:
User types in Chat: "Which of my S3 buckets or databases are publicly exposed?"
What happens in the background:
  1. Lambda fetches the active scan for Account 515554959344.
  2. It injects into Bedrock: "Context: Scan has 12 S3 buckets. Bucket 'finance-reports-prod' has BlockPublicAccess disabled and is publicly readable. RDS 'prod-postgres' is private."
  3. Bedrock Nova Pro responds immediately with the exact resource: "CRITICAL: S3 Bucket 'finance-reports-prod' in ap-south-1 is publicly exposed. Your RDS instances are safe. Run this CLI to fix it immediately: aws s3api put-public-access-block --bucket finance-reports-prod ..."

🚀 4. Key Architectural Benefits

🔐 Zero Agent Overhead

Customers don't need to install software agents or open inbound firewall ports. A standard CloudFormation template deploys a read-only cross-account role with a cryptographically secure External ID.

⚡ High-Speed Concurrency

Scanning all active AWS regions is executed concurrently with 12 parallel worker threads, completing enterprise discovery in seconds and avoiding API Gateway timeout limits.

🛡️ Grounded AI - Zero Hallucinations

Bedrock Nova Pro is strictly constrained by Amazon Bedrock Guardrails and fed live DynamoDB scan data. If a resource doesn't exist in the scan, the AI won't invent it.

📋 Complete Actionability

Generates instant executive audit reports, interactive blast-radius visual graphs, and copy-paste AWS CLI remediation scripts to fix vulnerabilities immediately.
